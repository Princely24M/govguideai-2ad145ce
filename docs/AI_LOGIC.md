# AI Logic

## Approach
Retrieval-grounded generation. The model is not trusted as a knowledge source for government facts;
it is used for language understanding, structuring and explanation over verified records.

## Pipeline
1. **Normalise** the question (lowercase, strip punctuation).
2. **Retrieve** — match against verified service records by slug, name, keywords and a synonym map
   (for example "identity", "ID book", "green book" → `smart-id`; "grant", "SASSA money" → grants).
3. **Ground** — inject the matched records (documents, steps, fees, processing time, authority,
   official URL, last-verified date) into the system prompt as the only permitted factual context.
4. **Generate** — call the AI Gateway with the system prompt plus the trimmed conversation history.
5. **Attribute** — return the matched records to the UI as source cards with authority, URL and
   last-verified date.
6. **Meter** — read provider-reported input/output/total tokens and persist them for the usage page.

## Conversational behaviour
- Maintains context across turns within a conversation.
- Asks a short clarifying question when the intent is ambiguous (for example "licence" could mean a
  learner's, driving or professional licence) instead of guessing.
- Breaks multi-step procedures into numbered steps.
- Signals uncertainty explicitly and defers to the official source when a detail is not in context.
- Never claims to be an official government authority.

## Guardrails
- No factual claim may originate outside the retrieved context.
- Fees, addresses, eligibility rules and deadlines are quoted only when present in verified data.
- When retrieval returns nothing, the assistant says what it does and does not cover, and points to
  the relevant department.

## Titles
Conversation titles are generated by a short, separate low-token model call summarising the first
question, then stored on the conversation row.

## Failure handling
Gateway errors return a structured `{ error }` payload; the UI renders a non-destructive error
message and keeps the question in history so the user can retry.
